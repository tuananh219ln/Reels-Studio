# 2026-11-26 — "Có gì mới": a changelog written by nobody, from the merged PRs

## Context

The owner wanted members to learn what changed after each deploy, with nothing to do for anyone: no changelog to
write, no step when opening a PR. Every PR here already has a Conventional Commits title written in Vietnamese
(`feat(video): MP4 tải lên, …`) and a Vietnamese "Làm gì và vì sao" section from the PR template.

## Decision

- **The source is the merged PRs.** The deploy of the web app reads them from GitHub and writes
  `public/changelog.json` with the app (`web/scripts/changelog.ts`). `feat` → "Tính năng mới", `fix` → "Sửa lỗi",
  `perf` → "Cải thiện"; every other type (and a title without one) is left out. The headline is the title after the
  colon, the detail the first paragraph of "Làm gì và vì sao" as plain text. No AI rewrites it: it costs nothing, needs
  no secret, and the titles are already short Vietnamese. If the wording turns out too technical for members, a
  rewrite by Claude in the deploy is the next step (a paid call per deploy, so a new decision).
- **No table of changes.** The file is rebuilt from GitHub on every deploy (the newest 60), so nothing is stored twice
  and a PR title fixed on GitHub is fixed in the app at the next deploy. The only state is each member's mark,
  `users.changelog_seen_at` (migration 0132), kept on the account so a change seen on the computer is not new on the
  phone. A member without a mark sees the last 3 days as new, not the whole history.
- **The window opens by itself** once per page load while something is new, and the bell keeps the history.
- **A tab open across a deploy is asked to reload** (a bar, never a forced reload: a member may be typing). It asks
  only when the newest change differs from the one the tab loaded, so a deploy of docs or tests alone asks no one.
- A failure to read GitHub only leaves the file out; the deploy is never stopped for it.

## Not done

Posting the changes to the team's chat and an MCP tool for Muse to read them (suggested with this feature) are left
for later.
