# 2026-11-10 — UI rules: one checked list of behaviour rules in ux-guidelines

Asked by the owner (namtc) on 2026-11-10, who found `docs/ux-guidelines.md` was not a usable standard: of its
1,200 lines, about 50 set rules (App Look) and the rest describe single screens, with nothing on
accessibility, focus, loading/empty/error states, copy, motion or phone width.

- A new "UI Rules" section sits after App Look and before Screens. It adapts Vercel's Web
  Interface Guidelines (the rules the `web-design-guidelines` agent skill checks) to an internal
  Ant Design app in Vietnamese: English-only rules (Title Case, Chicago style) are dropped,
  sentence case is kept, and "not a template" rules (no decorative gradients, emoji or filler copy)
  are added so the UI does not look AI-generated.
- App Look and every screen's section are unchanged. A screen section may still name an exception.
- Every gap found is fixed in the same change, on the owner's call ("làm hết 1 lượt rồi mới push"):
  the "Xem trước" playhead shows a focus ring when reached from the keyboard; the scene card's
  arrow stops turning under `prefers-reduced-motion` (Ant Design's own motion already did); long
  forms ask before typing is dropped; and list pages keep their search, filters, sort and tab in
  the address.
- The URL rule leaves out a table's page number (a filter change goes back to page 1 anyway) and
  the lists inside drawers, pickers and a Kho kiến thức group, whose open group is not in the
  address. Video's topic-group filter is still remembered in the browser as before; the
  address wins over it.
- The address is changed with `history.replaceState`, not `router.replace`: typing in a search
  box neither adds history entries nor asks the server for the page again.
